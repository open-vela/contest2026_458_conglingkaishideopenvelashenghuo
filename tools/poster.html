要解决的问题

  • 可穿戴语音助手一断网就完全失效
  • 只能「问一句答一句」，没有主动关怀
  • 端侧塞语音栈，算力与功耗都吃不下

我们的路线：端云职责切分

  • 端侧（openvela/NuttX）：确定性地执行。三级意图路由 + 5 项工具 + 主动引擎 + 记忆持久化，全部在 16K 栈的单任务内闭环，零算力、零联网依赖。
  • 云端（PC 网关）：负责听懂与生成。离线 Vosk 全局唤醒 + ASR，大模型按 OpenAI 兼容接口对接大赛 MiMo，无 Key 时降级本地 Mock，演示不会开天窗。
  • 断网降级：本地规则照常可用，云端不可达时明确提示「离线可用：提醒/备忘/时间/亮度/状态」，绝不静默无响应。

四个创新点

① 端云职责切分：端侧保证「断网也能执行」，云端负责「听懂与生成」。

② Skill 热加载：新能力以 Markdown 定义运行时热安装到板端 /data/agent/skills/，不重烧固件即可扩展。

③ 主动引擎：到点推送 / 久坐提醒 / 待办积压建议，且只基于真实运行状态触发， 不做虚假传感器数据演示。

④ 自研二进制帧协议：CRC16-CCITT 校验 + 流式坏帧重同步 + 有界写入（忙时丢帧保链路），板端 C 与上位机 Python 逐字节互操作验证。

手表端 UI（LVGL 9.2，触摸左右滑动）
