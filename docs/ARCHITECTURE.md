# 架构与协议

> 帧类型数值的**唯一真源**是 `app/wristclaw/wc_proto.h` 与 `host/wristclaw/protocol.py`，
> 两者必须一致；本文档只做说明，如有出入以代码为准。

## 一、端云分工

```
        PC 网关 (host/)                            开发板 (app/wristclaw)
┌──────────────────────────────────┐        ┌──────────────────────────────┐
│ 麦克风 → Vosk 常驻唤醒            │        │ 意图路由 (本地规则优先)       │
│        → 录音 → ASR              │        │   ├ 提醒/备忘/时间/亮度/状态  │
│        → USER 帧 ────────────────┼──┐     │   ├ Skill 触发词              │
│                                  │  │     │   └ 交云端                    │
│ 云端 Relay (MiMo / mock)         │  │USB  │ 工具执行 (真实动作)           │
│  ├ ASR / TTS                     │  │CDC  │ 主动引擎 (到点/久坐/积压)     │
│  └ 对话 / 结构化动作             │  │1Mbps│ 记忆持久化 (/data/wristclaw)  │
│                                  │  │     │ Skill 热加载 (/data/agent)   │
│ 收到 SAY 帧 → 显示 / TTS  ◄──────┼──┘     │ LVGL UI (表盘/对话/提醒)      │
│ 连接后校时 TIME ─────────────────┼───────►│ clock_settime + 时区偏移      │
└──────────────────────────────────┘        └──────────────────────────────┘
```

设计原则：**端侧保证"断网也能执行"，云侧负责"自然语言理解"**。
本地规则命中时完全不依赖网络；判不了才上行云端（`{"req":"chat","q":...}`
或带 Skill 提示词的 `{"skill":...,"prompt":...,"q":...}`）。

## 二、帧格式

```
偏移  0      2      3       4        6       8..N        N+2
     ┌──────┬──────┬──────┬───────┬────────┬──────────┐
     │0xAA55│ TYPE │ SEQ  │  LEN  │ PAYLOAD│ CRC16    │
     │  2B  │  1B  │  2B  │  2B   │  变长  │   2B     │
     └──────┴──────┴──────┴───────┴────────┴──────────┘
              LEN 最大 2048，CRC16-CCITT (0x1021, init 0xFFFF)
              坏帧按流式重同步（丢掉一个字节后继续找 0xAA55）
```

| TYPE | 名称 | 方向 | 说明 |
|---|---|---|---|
| 0x01 | TEXT | 双向 | 板→PC：Agent 输出文本；PC→板：`USER <文本>` 走意图路由，其余行进 `wc_agent_handle_cloud_reply()` |
| 0x02 | AUDIO_DATA | 双向 | 预留（板端音频通路未实现，见 docs/DEMO.md 第十节） |
| 0x03 | AUDIO_CMD | 双向 | 预留（同上） |
| 0x04 | CLOUD_REQ | 板→PC | 上行云端请求，载荷为 JSON 文本 |
| 0x05 | CLOUD_RESP | PC→板 | 云端结果 / 行协议命令（见下） |
| 0x06 | DEVICE_CMD | PC→板 | 设备命令（`wc_agent_handle_device_cmd`） |
| 0x07 | DEVICE_STATUS | 板→PC | 设备状态上报 |
| 0x08 | WAKE_EVENT | 板→PC | 唤醒事件（端侧唤醒实现后启用） |
| 0x09 | ACK | 双向 | 心跳应答 |
| 0x0A | HEARTBEAT | 双向 | 板端每 3s 一次，上位机据此判在线 |
| 0x11 | SENSOR_DATA | 板→PC | 预留（本板无生物传感器，本期未使用） |
| 0x12 | REMINDER | 板→PC | 提醒到点主动推送 |

### 行协议（承载在 CLOUD_RESP / TEXT 的载荷里）

板端只需要按行前缀分发，不需要 JSON 解析，降低端侧负担：

| 命令 | 方向 | 说明 |
|---|---|---|
| `SAY <文本>` | PC→板 | 让板端显示/播报一句话 |
| `REMIND <秒> <文本>` | PC→板 | 让板端建一个提醒 |
| `MEMO <文本>` | PC→板 | 存入备忘 |
| `BRIGHT <0-100>` | PC→板 | 设背光 |
| `SKILL <name>\|<triggers>\|<tool>\|<prompt>` | PC→板 | 热安装一个 Skill（落盘 + 热加载） |
| `SKILLS` | PC→板 | 列出已加载 Skill |
| `TIME <epoch 秒> <时区分钟>` | PC→板 | 校时 + 设时区偏移 |
| `USER <文本>` | PC→板 | 走完整意图路由（语音/文本输入） |

## 三、典型时序

### 1. 建链（顺序至关重要）

```
板端 app                            主机 (host/app.py 或 bridge.py)
   │                                   │
   │  open("/dev/ttyACM0") ── 失败 ──── │  open("COM10")  ← 先打开，DTR 置位
   │  ENOTCONN(107) 每 2s 重试          │  （cdcacm 只在主机配置后才 connected）
   │                                   │
   │  open() 成功 ←────────────────────┘
   │  "link up on /dev/ttyACM0"
   │  问候 + 状态 TEXT ────────────────►  显示
   │  心跳 每 3s ─────────────────────►  （上位机据此判在线，并回 ACK）
   │  ◄──────────────── TIME <epoch> <tz>  校时（连接后立即 + 每 60s）
```

### 2. 一次语音交互

```
用户说话 → Vosk partial 命中唤醒词 → 提示音 → 录音 → ASR
  └→ USER <text> ──► 板端路由
                       ├ 本地命中 → 立即执行 + SAY（离线可用）
                       └ 未命中   → CLOUD_REQ(0x04) → 云端 → CLOUD_RESP(0x05)
                                                              └→ 行协议动作
```

### 3. 主动推送（无请求触发）

```
板端 proactive_tick (1Hz)
  ├ 提醒到点      → SAY【提醒】+ REMINDER(0x12) 帧 + UI 卡片
  ├ 久坐阈值      → 【主动提醒】
  └ 积压 ≥3 条    → 【主动建议】
```

### 4. 校时（板端无 RTC 备份电池，必须由主机给时间）

```
连接建立 → 主机发 TIME <epoch> <时区分钟>
板端 → clock_settime(CLOCK_REALTIME, ...)
     → 记录时区偏移（openvela 侧未启用 TZ，用 gmtime_r(utc + offset) 换算）
     → 首次校时应答 "时间已同步：HH:MM"
未校时期间表盘显示 --:-- / "等待上位机校时"（不显示 1970 假时间）
```

## 四、可靠性策略（都由实测缺陷驱动）

| 策略 | 原因 |
|---|---|
| 写入"有界重试 + 丢弃"，`-2` 表示忙丢帧 | 主机暂时没读是常态；误当链路错误会导致拆绑风暴，饿死主机侧打开操作 |
| 仅真错误（ENODEV 等）才拆链路重连 | 同上 |
| 请求组装缓冲置静态 | 16K 栈上放 2KB 缓冲 + 深层调用链 = 硬故障死机 |
| 板端只在主机 DTR 置位后绑定 | cdcacm 的 connected 语义；先主机后板端是唯一稳定顺序 |
| 一个板端实例 | 多实例竞争同一 tty，把主机 RX 撑爆 |
| 大数组一律静态 | 持久化路径曾把 `char[N][96]` 强转 `char**` 传给 `fprintf`，野指针硬故障 |
